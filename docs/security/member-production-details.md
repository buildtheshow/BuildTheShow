# Member production details

My Activities keeps the approved compact production cards: poster, title and selected member's role(s). Circle cards combine role labels without listing private account information. A card opens `/member/activities?production=<id>&profile=<id>` (or a circle filter). The list is hidden on the detail view; All productions returns to the same selected profile/circle. The existing shared purple member navigation retains its named icons and visible labels, including My Calendar as a separate page.

The detail view reuses production data rather than mockup content: organisation, description, venue/address, profile-specific contacts, dress rehearsals, rehearsals, performances, audition bookings, volunteer shifts and permitted files. Payment details remain conditional, with Fee breakdown, Payment schedule, Payments received and How to pay in the established order.

`bts_member_production_details(uuid,uuid)` requires an active adult login, management access to the selected profile and an active audition, volunteer or accepted account-bound team relationship with that production. Organisation ownership alone does not grant a family profile a production role. The frontend queries only the authorised members of the selected circle who participate in that production. Profile IDs, rather than names, determine membership; identical names cannot cross scopes.

Contacts use active production team roles: volunteer coordinator for volunteers, producer/production manager for production matters, with the organisation's published contact as a fallback. Mixed-role participants can receive both contacts. Only name, role, email and phone are returned, never a directory, passcode or invitation token. Missing contact information is stated plainly.

Cast call filtering uses the existing `called_cast` and legacy `called_character_ids` fields against that profile's accepted casting assignments. A call list marked TBD is labelled unconfirmed. Public events for someone else's cast role remain informational and cannot become a confirmed call. Volunteer shifts come from the member's existing requests and assignments. Creative team events obey existing calendar permissions. Arrival, bring and preparation notes are projected explicitly; private staff notes and other people's call lists are omitted. Venue projection includes only name/address.

Files remain governed by existing permissions and storage signing. Working files require that the selected profile is the caller's accepted staff profile and the caller has existing overview file permission. Callback files additionally require an actual callback for that selected profile and existing callback/file permission. This change does not publish staff files to cast or volunteers. File links are signed on request; failed opens display an error.

No new tables or data storage. Migration: `20261122110000_member_production_details.sql`. Other pending migrations, including transactional audition booking, remain untouched.
