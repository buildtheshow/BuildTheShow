# Compact member Activities

My Activities uses the approved 40px round headshot selectors with names beneath. Profiles and circles are separate accessible groups with a small visual gap and no visible group headings. The selected circle includes only attached profiles the current adult is allowed to manage. Switching selections updates the show cards, role offers, schedule and volunteer details without discarding the full authorised snapshot. The selected member is also passed to the existing single-profile application tools. Circle users choose a member before opening those tools.

The poster cards reuse the organisation dashboard's production-card poster-frame/body conventions and 8.5/11 aspect ratio, at the approved compact 120px width. Each links to its show detail view with the selected profile or circle preserved. Character names are resolved through the existing participant-casting and visible-character views, using both application and booking references. Character names are displayed only for accepted cast offers/registrations or accepted assignments; an internal chosen assignment does not announce a role. Volunteer captions use the actual saved role, such as set construction or usher. Audition bookings and applications retain their own labels. No sample names, headshots or posters from the mockup are used in the live data.

Profile photos come from the existing authorised profiles query, limited to known accessible profile IDs. The existing `BTSPrivateMedia.authorisedUrl` helper signs private headshots before display. Signed URLs stay in memory and the DOM. A missing/denied photo uses the existing performer icon. Production posters come from the existing safe productions view. Missing/broken posters use `Placeholder - Poster.svg`. Image URLs are limited to HTTP(S); captions and attributes are escaped. Optional media/role query errors have a visible retry note.

Calendar remains a tab inside My Activities. Detailed tools and shifts open for a selected show or the existing shifts link; large profile cards and the duplicate find-opportunities band are removed from the Activities overview. The approved Home layout is unchanged. No schema, data migration, access policy or email change was required.

Verification: `member-activities-browser.cjs` checks the actual page with synthetic responses: signed-media-helper use, photo/icon and poster fallbacks, correct character/volunteer captions, unpublished-role suppression, explicit member/circle scope, show links, calendar and 320/390/768/1280px layouts. Existing Home and unified-account browser checks cover shared-page regressions. No real account records or emails are written.
